# وثيقة تصميم: مكتبة تسليم المرئيات (موقع مستقل)

التاريخ: 2026-10-28 (مراجعة 2 بعد فحص مستودع الموقع وإجابات المالك)
الحالة: جاهزة للموافقة
المرجع البحثي: `reports/تصميم مكتبة تسليم المرئيات.md`
الموقع الأم: مستودع `wilt` (EMDATRA على wallt.emdatra.org)

---

## 1. المقصد والسبب

مؤسسة EMDATRA تنفّذ مشاريع ميدانية ويوثّقها مصوّرون بالصور والفيديو. المستفيدون من هذا التوثيق (الجهات التي نسمّيها «العملاء») يحتاجون موادّ مشاريعهم منظّمة، يشاهدونها فورًا وينزّلونها بسهولة. اليوم تُسلَّم المواد عبر Drive وروابط متفرقة، فيضيع العميل وتتراكم مشاريع الشهور بلا أرشيف يُبحث فيه.

المطلوب: **مكتبة مستقلة** على نطاق فرعي (مثل `media.emdatra.org`)، تظهر في الموقع الأم كقسم باسمها، وتفتح بضغطة واحدة بجلسة المستخدم نفسها. يديرها مدير عام، يرفع إليها عدة مصوّرين، ويستلم منها العملاء عبر روابط خاصة.

المبدأ الحاكم: **المرئيات وحدها ملوّنة**. كل ما عداها هادئ ومحايد ويتراجع.

## 2. الأدوار

| الدور | من هو | ما يراه | ما يفعله |
|---|---|---|---|
| **المدير العام** | مستخدم admin في الموقع الأم | كل العملاء والمشاريع والمصوّرين والأرشيف | ينشئ العملاء والمشاريع، يسند لمصوّرين، يراجع، ينشر، يولّد الروابط ويرسلها، يبحث ويفلتر، يستورد من Drive، يصدّر |
| **المصوّر (مؤلف)** | مستخدم في الموقع الأم بصلاحية «مكتبة: إضافة» | المشاريع المسندة إليه فقط | يرفع الصور (RAW وJPEG) والفيديو، يرتّب، يعلّم «جاهز للمراجعة» |
| **العميل** | جهة مستفيدة، بلا حساب | مكتبته: كل مشاريعه عبر الزمن | يتصفح، يشاهد (بما فيها الرشزات)، ينزّل ملفًا أو قسمًا أو المشروع كاملًا |

المدير والمصوّرون يدخلون بحسابات الموقع الأم نفسها (لا تسجيل جديد). العميل يصل برابط + رمز PIN من 4 أرقام.

## 3. الأهداف وغير الأهداف والأهداف المضادة

**أهداف:**
- العميل يصل إلى الملف الذي يريده خلال ثلاث ضغطات من فتح الرابط.
- الفيديو، بما فيه الرشزات الخام، يبدأ العرض خلال ثانيتين على شبكة هاتف.
- رفع ملف 20 GB يكتمل رغم انقطاع الشبكة أو إغلاق التبويب، دون أن يمرّ عبر السيرفر.
- المدير يجد أي مشروع من الشهور الماضية خلال 10 ثوانٍ عبر الفلاتر.
- الأرشيف القديم على Drive يُستورد إلى المكتبة بأداة لا بالنقل اليدوي.
- الواجهة كاملة بالعربية (RTL) والتركية (LTR) بجودة متساوية.

**غير أهداف (الإصدار الأول):**
- التعليقات والمراجعة المثبّتة على الإطار. للإصدار الثاني.
- اختيار العميل لصور «مفضّلة» تعود للاستوديو. للإصدار الثاني، والتحديد المتعدد يُصمَّم ليستوعبه.
- تحرير الفيديو داخل المكتبة (الموقع الأم يملك محرّرًا بالفعل).
- تطبيق أصلي منفصل: الإصدار الأول ويب متجاوب، يُفتح من تطبيق Flutter الحالي كرابط أو WebView.

**أهداف مضادة (فشل حتى لو عمل تقنيًا):**
- واجهة ملوّنة أو مزدحمة تنافس الصورة على الانتباه.
- عميل يحتاج شرحًا لمعرفة كيف ينزّل.
- رابط ينتهي بصمت فيضيع العميل.
- صور تتشوّش عند التكبير على الهاتف.
- واجهة تركية أو عربية تبدو «مترجمة» أو مقلوبة.
- مكتبة تبدو جزيرة غريبة عن الموقع الأم في الدخول أو الخط.

## 4. القيود (مقيسة من المستودع)

- **البنية القائمة:** VPS بحاويات Docker خلف Caddy (يملك المنفذين 80 و443)، MariaDB، PHP 8.3 للموقع الأم، النشر من GitHub عند الدفع إلى main. المكتبة تُضاف **حاوية جديدة** في `docker-compose` نفسه ونطاقًا فرعيًا في Caddy.
- **التخزين:** دلو Cloudflare R2 قائم (مفاتيحه عند المالك خارج Git). المكتبة تستخدم الدلو نفسه ببادئة مسار خاصة بها.
- **المنطقة الزمنية:** الموقع الأم يعمل على `Asia/Hebron`. تُعتمد نفسها للانتهاء والتواريخ.
- **اللغات:** عربي (أصل) وتركي. الموقع الأم يترجم بقاموس ثابت عربي ← تركي؛ المكتبة تملك قاموسها الخاص بالآلية نفسها (نصوص عربية أصلية ومقابل تركي).
- **الخط والهوية:** الموقع الأم يستعمل IBM Plex Sans Arabic وألوان Deep Indigo `#3658CC` وTeal `#06B0AA` وNavy `#0B1839`. المكتبة تحتفظ بالخط، وتستعمل **Teal واحدًا** لونَ تمييز وحيد. (قراري بناءً على «أنت اقترحه»)
- **حدود R2:** الأجزاء 5 MiB–5 GiB متساوية، 10,000 جزء، روابط موقّعة ≤ 7 أيام، Worker ≤ 100 MB.
- **iOS Safari:** لا Background Fetch ولا File System Access. التنزيل الضخم رابط موقّع.
- **الوصولية:** WCAG 2.2 AA حدًا أدنى.

## 5. نموذج المحتوى

```
عميل (جهة مستفيدة: اسم، لغة الواجهة ar/tr، رمز PIN، رابط ثابت)
 └─ مشروع (اسم، نوع المشروع، تاريخ التصوير، المكان، المصوّرون المسندون، الحالة، تاريخ الانتهاء)
     ├─ قسم الصور
     │    ├─ مجموعة «نهائي» (JPEG)
     │    └─ مجموعة «خام» (RAW: CR3/NEF/ARW/DNG)
     └─ قسم الفيديو
          ├─ مجموعة «نهائي» (الأفلام المنتَجة)
          └─ مجموعة «رشزات» (اللقطات الخام، تُشاهَد بالبث وتُنزَّل أصلًا)
```

- أبعاد التصنيف تُستعار من الموقع الأم: نوع المشروع، الجهة المستفيدة (= العميل)، الفريق المنفّذ، تاريخ التصوير، المكان.
- **الحالات:** مسودة ← قيد الرفع ← جاهز للمراجعة ← منشور ← منتهٍ (مخفي لا محذوف).
- **رابط العميل:** مكتبة دائمة تعرض كل مشاريعه (الأحدث أولًا). المدير يستطيع إرسال رابط مشروع يفتح على مشروع بعينه داخل المكتبة نفسها. رابط ضيف منفصل (مشاهدة فقط لمشروع واحد).
- **الانتهاء:** يُطبَّق على المشروع. الافتراضي 90 يومًا، يُخفى عند 23:59 بتوقيت Asia/Hebron، والتاريخ مطبوع في صفحة العميل مع تذكير قبل 7 أيام.
- **التنزيل:** صور: الأصل (RAW أو JPEG) أو حجم ويب 2048px. فيديو: الأصل أو 1080p.
- **الاحتفاظ:** لا حذف تلقائي. بعد 90 يومًا من الانتهاء تُنقل الأصول (RAW والرشزات أولًا) إلى طبقة R2 Infrequent Access. الحذف يدوي بتأكيد.
- **بيانات كل ملف:** الاسم، النوع، الحجم، المدة أو الأبعاد، تاريخ التصوير، المصوّر، مصدر الالتقاط (هاتف/كاميرا)، الوسوم، عدد التنزيلات.

## 6. المسارات الأساسية

### المدير
1. **الدخول:** يضغط «مكتبة المرئيات» في الموقع الأم ← يفتح النطاق الفرعي بجلسة جاهزة بلا كلمة مرور ثانية.
2. **إنشاء مشروع:** عميل (جديد أو قائم) ← اسم ← نوع ← تاريخ التصوير ← إسناد مصوّر أو أكثر ← حفظ. أقل من دقيقة.
3. **المراجعة:** قائمة «بانتظار المراجعة» على لوحة البداية. يفتح المشروع، يرى القسمين، يحذف أو يعيد الترتيب، يضغط «نشر».
4. **التسليم:** «إنشاء رابط» ← الرابط والـ PIN وتاريخ الانتهاء ← «نسخ» أو «إرسال» (واتساب/بريد عبر Web Share). الـ PIN يُرسَل منفصلًا.
5. **البحث في الأرشيف:** شريط فلاتر دائم الظهور: مدى زمني، عميل، مصوّر، نوع مشروع، نوع مادة، حالة، وسوم. بحث نصي يفهم «الزفاف» = «زفاف» و«istanbul» = «İstanbul». الأحدث أولًا. تحرير جماعي (نشر، تمديد، أرشفة).
6. **الاستيراد من Drive:** يربط حساب Google Drive مرة ← يختار مجلدات ← يُسند كل مجلد إلى عميل ومشروع (مع اقتراح تلقائي من اسم المجلد وتاريخه) ← السيرفر ينسخ الملفات من Drive إلى R2 مباشرة في الخلفية ← تقرير بما تم وما فشل. لا يمرّ الملف عبر متصفح المدير.
7. **التصدير الإداري:** تنزيل مشروع كامل متجاوزًا الـ PIN.

### المصوّر
1. يدخل من الموقع الأم بالجلسة نفسها، فيرى المشاريع المسندة إليه ومواعيدها.
2. يسحب الملفات أو يختارها ← تبدأ مباشرة إلى R2 بأجزاء ← قائمة رفع بتقدم لكل ملف وإيقاف/استئناف ← عند إغلاق التبويب وإعادة اختيار الملف نفسه يُستأنف من حيث توقف.
3. يختار القسم والمجموعة قبل الرفع أو بعده بالسحب. RAW يذهب تلقائيًا إلى «خام».
4. يضغط «جاهز للمراجعة». يصله إشعار عند النشر.
5. الرفع من الهاتف مدعوم للصور والدفعات الصغيرة مع تنبيه أن إغلاق التطبيق يوقف الرفع.

### العميل
1. يفتح الرابط ← صفحة واحدة: شعار المؤسسة، اسم العميل، حقل PIN.
2. **مكتبتي:** بطاقات مشاريعه بغلاف وتاريخ وعدد الملفات، الأحدث أولًا، فلتر تاريخ بسيط.
3. **صفحة المشروع:** غلاف بعرض الشاشة ثم تبويبان كبيران: **الصور** / **الفيديو**. داخل كل تبويب مجموعاته (نهائي/خام أو نهائي/رشزات).
4. شبكة مبرَّرة للصور، وبطاقات 16:9 للفيديو مع المدة ومعاينة تمرير.
5. ضغطة على صورة ← عارض بلا قشرة على أسود خالص، سحب للتنقل، قرص للتكبير بطبقة أعلى دقة، سحب لأسفل للإغلاق. صور RAW تُعرض عبر معاينتها المضمّنة.
6. ضغطة على فيديو ← مشغّل بث تكيّفي يبدأ فورًا، اختصارات لوحة مفاتيح قياسية، PiP. الرشزات تُشاهَد بالطريقة نفسها.
7. **التنزيل:** زر «تنزيل» صريح على كل عنصر وفي العارض؛ تحديد متعدد يُظهر شريطًا عائمًا بعدّاد وزر «تنزيل المحدد»؛ «تنزيل الكل» لكل قسم وللمشروع. ZIP يبدأ فورًا.
8. مفتاح لغة عربي/تركي في رأس الصفحة؛ الافتراضي لغة العميل التي حدّدها المدير.

## 7. الشاشات

**المدير:** لوحة البداية (بانتظار المراجعة، آخر الروابط، رفع جارٍ، استيراد جارٍ) • الأرشيف (قائمة + شريط فلاتر) • صفحة مشروع (قسمان، إدارة الملفات، الروابط، السجل) • العملاء • المصوّرون • الاستيراد من Drive • الإعدادات (الانتهاء الافتراضي، المنطقة الزمنية، الشعار).

**المصوّر:** مشاريعي • صفحة مشروع مع منطقة الرفع وقائمة التقدم.

**العميل:** بوابة الدخول (PIN) • مكتبتي • صفحة المشروع • عارض الصور • مشغّل الفيديو • شريط التحديد العائم.

كل شاشة بالاتجاهين (عربي RTL، تركي LTR) وعلى مقاسين على الأقل: هاتف 390px وسطح مكتب 1440px.

## 8. الاتجاه البصري (ملخص DESIGN.md)

- **الألوان:** رمادي محايد بكروما 0 (سلّم Tailwind neutral في OKLCH). خلفية التطبيق `#fafafa` فاتحًا و`#0a0a0a` داكنًا. أسود خالص `#000` داخل العارض والمشغّل فقط. حدود شعرية شفافة 8%. لون تمييز واحد: **Teal `#06B0AA`** من هوية الموقع الأم للأفعال الأساسية وحلقة التركيز. الداكن افتراضي لصفحات العميل، الفاتح افتراضي للوحة المدير، مع مفتاح تبديل.
- **الخط:** IBM Plex Sans + IBM Plex Sans Arabic (مع latin-ext للتركية)، نفس عائلة الموقع الأم. الأوزان 400/500/600. سلّم 1.2، جسم 16px، العربية +2pt وارتفاع سطر ≥1.5. أرقام 0–9 افتراضيًا مع مفتاح «أرقام مشرقية». أرقام جدولية للمدد والأحجام.
- **الزوايا:** 6px للحقول، 10px للبطاقات، 16px للألواح، 0 داخل العارض.
- **الطبقات فوق الصور:** كبسولة `rgba(0,0,0,0.6)` للمدة، حجاب متدرج `0.64 → 0` عند 48% للتحديد، مربع تحديد 24×24 بحلقة بيضاء 2px، أزرار 32×32 (44 باللمس).
- **الحركة:** 120/200/320ms بمنحنى `cubic-bezier(0.2,0,0,1)`. فتح العارض تلاشٍ وتكبير ≤2%. معاينة التمرير بعد 300ms ولا تعمل باللمس. تحت `prefers-reduced-motion` يبقى التلاشي فقط.
- **الأيقونات:** Lucide بسمك 1.5px. قائمة سماح للانعكاس في RTL (أسهم، شيفرونات، رجوع/تالٍ، رد، مسافة بادئة)؛ لا تُقلب أزرار التشغيل والتخطي والساعة والصح والبحث والتنزيل والشعارات.
- **القشرة** في العارض تختفي بعد 2.5 ثانية ولا تحجب العنصر المركَّز.

## 9. القرارات التقنية (مقررة)

| الطبقة | القرار |
|---|---|
| **الشكل** | موقع مستقل على نطاق فرعي، حاوية جديدة في docker-compose القائم خلف Caddy |
| **الدخول الموحّد** | الموقع الأم يُصدر رمزًا موقّعًا قصير العمر (نمط `media_sig_lib` القائم: HMAC مع هوية المستخدم ودوره وصلاحية المكتبة) عند الضغط على القسم؛ المكتبة تتحقق منه وتفتح جلستها الخاصة. لا كلمة مرور ثانية ولا نسخ للمستخدمين |
| الرفع | Uppy `@uppy/aws-s3` بوضع signRequest، أجزاء ثابتة 64 MiB، استئناف عبر ListParts وبصمة ملف. السيرفر يوقّع والمتصفح يبثّ مباشرة إلى R2 (المنطق نفسه الذي أثبته `r2_lib.php` مع CORS وExposeHeaders: ETag) |
| الفيديو | ffmpeg في حاوية عاملة: H.264 حتى 1080p + SVT-AV1 لـ 1440p/4K، CMAF/fMP4، الدرجة الدنيا أولًا؛ شرائح WebVTT للتمرير. لقطات الهاتف (الأغلب) تُرمَّز بسرعة لدرجة واحدة أولًا ثم الباقي |
| المشغّل | Video.js 10 + hls.js |
| الصور | libvips/sharp ببناء يضم libheif وLibRaw؛ RAW: معاينة JPEG المضمّنة أولًا ثم فكّ كامل عند الحاجة؛ AVIF → WebP → JPEG؛ ThumbHash |
| التنزيل الجماعي | ZIP64 متدفق بوضع STORE من السيرفر؛ فوق ~20 GB روابط موقّعة لكل ملف |
| الاستيراد من Drive | Google Drive API بتفويض OAuth للمدير؛ عامل خلفي ينقل الملفات من Drive إلى R2 بتدفق مباشر، مع مطابقة الاسم والتاريخ لاقتراح العميل والمشروع |
| الطابور | Graphile Worker على Postgres + حاوية ffmpeg/libvips منفصلة |
| قاعدة البيانات | Postgres خاصة بالمكتبة (منفصلة عن MariaDB الموقع الأم)؛ العلاقة بالموقع الأم عبر هوية المستخدم في الرمز الموقّع فقط |
| الأمن | JWT لكل رابط عميل (client_id, scope, exp, jti) + PIN؛ تحقق قبل الكاش؛ 302 إلى رابط موقّع 5–15 دقيقة للأصول |
| الإطار | Next.js 16.4 App Router، `next start` في الحاوية |
| الشبكة | `@immich/justified-layout-wasm` + TanStack Virtual |
| العارض | yet-another-react-lightbox (يكتشف dir تلقائيًا) |
| البحث | Meilisearch 1.56 في حاوية (الوحيد الموثّق للعربية والتركية معًا) |
| التدويل | next-intl، `dir` على `<html>` من الخادم، خصائص CSS منطقية، numberingSystem صريح |
| المكوّنات | shadcn/ui بقاعدة React Aria |

**ما يُستعار من المكتبة القائمة في `wilt`:** منطق توقيع R2 وقائمة CORS، أبعاد التصنيف (نوع المشروع/الجهة/الفريق/التاريخ/المكان)، نمط روابط المشاركة بعدّاد الفتح وانتهاء 410، نمط الرمز الموقّع في `media_sig_lib.php`، الخط وألوان الهوية. **ما لا يُنقل:** واجهتا `library.js` و`library-workspace.js`، محرّر الفيديو، التفريغ النصي.

## 10. المتروك للبانين

- مخطط Postgres وتفاصيل الـ API.
- GPU أم CPU لحاوية ffmpeg حسب عتاد السيرفر.
- قناة الإشعارات (بريد، واتساب، داخل الموقع الأم).
- خوارزمية اقتراح العميل/المشروع من أسماء مجلدات Drive.
- ترخيص `@immich/justified-layout-wasm` (AGPL) أو بديل MIT.
- إضافة البلاطة والرابط في شريط الموقع الأم (تعديل صغير في `index.php` و`api.php` لإصدار الرمز).

## 11. قراراتي المعلَّمة
